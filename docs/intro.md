# 被微信读书接口堵了以后,我自己搞了一套公众号管理工具

> 起因很简单:之前一直靠微信读书的一个接口拉关注公众号的文章列表,
> 那个接口最近被堵了 —— 一夜之间,我的公众号文章流就断了。

公众号数据获取这件事,其实开源圈早就有人在干。我大致看了下两条主流路径:

- **「拿到 URL 转 Markdown」**:把 `mp.weixin.qq.com/s/xxx` 这种文章链接转成干净的 Markdown。
  代表项目:[jackwener/wechat-article-to-markdown](https://github.com/jackwener/wechat-article-to-markdown),
  1k stars,PyPI 发布,主打 Camoufox 反检测抓取 —— 它解决的是「**一篇文章**」的工程问题。
- **「从本地数据库起手」**:直接把微信桌面端的加密数据库解开,自己取公众号元数据。
  这条路的代表性文章是[凉糕的《基于本地数据库的微信公众号转 RSS 方案》](https://osnsyc.top/posts/wechat-db-to-rss/),
  思路很朴素 —— 把数据库里的 `biz_message_0.db` 解出来,
  生成标准 RSS 文件,丢给任意 RSS 阅读器。

这两条我之前都用过,前者适合「**收到一篇文章链接就转**」,
后者适合「**订阅一个号、看它的更新流**」。

但都满足不了我想要的「**每天 100 多个号一起看一遍,然后告诉我今天该读什么**」。
所以我就自己拼了一套 —— 用 chatlog(凉糕文章里也提到的那个解密工具)做底座,
在上面盖了一层管理面板和 LLM 摘要,起个名叫 **bizhub**。

## 这套东西能干什么

一个核心:**把你关注的公众号,变成一个可以主动梳理的工具**。
具体讲,它做下面这几件事 ——

### 1. 把关注的公众号从微信里挖出来

微信桌面端的本地数据库会把公众号消息存下来。我做的是把这部分解出来,
按账号(ghid)和文章维度统一归到一个本地 SQLite,后面所有功能都以这张表为基础。
全程在你自己电脑上跑,数据不上任何云。

> 📍 截图位 2:解出来的数据库 / 关注的号列表

### 2. 拿到 URL 不算完,把正文也抓下来

光有链接没法读 —— 还得去 `mp.weixin.qq.com` 把正文抓下来。
内置一个简单的抓取器,跑完后正文存进 `biz_article_contents` 表,
**30 天内的同一篇文章不再重新抓**(省时间,也减少被反爬的概率)。
正文中图片会被替换成占位符,链接会被单独标注,后面喂给 LLM 的时候它能看到上下文和参考链接。

> 📍 截图位 3:抓下来的文章正文展示(或 fetch 缓存日志)

### 3. 每天给我一份「今日看点」

每天关注的号可能有上百个,如果不分类、不打分,基本就是收藏夹吃灰。
bizhub 会拿当天的所有文章(以及可选近 N 天)丢给 LLM,
让它输出结构化字段:

- **summary**:今天整体讲了什么(两三段)
- **themes**:今天讨论的几大主题(可点击筛文章)
- **mustReads**:必读文章 + 评分 + 一句理由
- **byAccount**:按公众号分组,这个号今天讲了啥
- **highlights**:几条「这个号今天最值得看的一句」

而且每次摘要可以挂一个自定义指令,比如:

- 「只看 AI 算力」
- 「对比昨天的汇总,有什么新变化」
- 「三句话给我一份简报版」

不同指令会存成不同 `summary_type` 记录,历史报告都在,随时翻。

> 📍 截图位 4:今日看点页(汇总 + 主题卡 + 必读评分 + byAccount)

### 4. 一个 Web 面板管所有事

不用每次开命令行。打开浏览器进 `http://127.0.0.1:5030/biz`,
顶部四个 tab:

| 页面 | 干什么用 |
|------|----------|
| **文章浏览** | 按账号分组的文章流 + 搜索 + 同步 + 标签筛选 |
| **关注动态** | 默认近 7 天,左侧 LLM 主题/关键词面板 + 文章收藏 ☆★ |
| **汇总** | 今天的「看点」+ 历史报告 |
| **管理** | 账号显隐 / 星标 / 批量打标签 / 标签 CRUD |

日常用最频繁的两个动作:**「只看收藏」** 过滤、**「批量给账号打标签」**。

> 📍 截图位 5:Web 主界面(四个 tab 顶部可见)

### 5. 左侧那个 AI 摘要面板

每次打开「关注动态」,左侧都会刷出一栏结构化摘要:

- `headline`:一句话今日要点
- `themes`:主题列表(可点击筛文章)
- `keywords`:高频词(可点击筛文章)
- `hotTakes`:几条「这个号今天讲了什么」短评

**4 小时缓存**,想强刷就带 `?fresh=true`。

## 它跟前面两条路有什么不一样

| | URL → Markdown | 本地 DB → RSS | bizhub(我这套) |
|---|:---:|:---:|:---:|
| 数据来源 | 你给它一个 URL | 本地数据库解密 | 本地数据库解密 |
| 输出形态 | 一篇 Markdown | 一组 RSS 文件 | 网页 + LLM 摘要 |
| 适合 | 转发单篇 | 订阅一个号 | **日常看一堆号** |
| 摘要 | 没有 | 没有 | **结构化多字段** |
| 筛选 / 标签 | 没有 | 靠 RSS 阅读器 | **内嵌 Web** |
| 多账号(微信) | 不限 | 不限 | 支持 |

简单讲:第一条路是「**拿到文章 -> 读**」,
第二条是「**号 -> 订阅看**」,
我这套是「**一堆号 -> AI 帮你筛**」。

## 现在它在我的工作流里

目前我的公众号流是断的(微信读书接口堵了),这是我**唯一稳定的一条链路**。
每天起床后第一件事就是打开这个面板,扫一眼「今日看点」,
然后翻左侧「hotTakes」挑有兴趣的号深读。

后续我打算再补两块功能:

- **更细的自动分组**:LLM 按主题自动聚合文章,自动打标签
- **跨号合并阅读**:同一事件被多个号报道时,合成「专题」

这两个做完之后,这工具就基本满足个人公众号阅读的全部需求了。
